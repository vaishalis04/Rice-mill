1. Business Process Flow

GATE ENTRY → TOKEN/QUEUE → SAMPLING → LAB TESTING → (NEGOTIATION) → WEIGHBRIDGE (GROSS)
   → UNLOADING → [STORE IN WAREHOUSE]  OR  [DIRECT TO PRODUCTION]
   → QUICK QC (bag-level) → MOISTURE DECISION → (DRYER if wet) → MILLING
   → SEPARATOR → WHITENING/SHINER (1-5) → COLOR SORTER → LENGTH GRADER
   → PACKING (batch/lot/barcode/QR) → FINISHED GOODS WAREHOUSE
   → SALES ORDER → DISPATCH (Invoice/Challan/Loading Slip) → WEIGHBRIDGE (TARE/NET)
   → GATE-OUT

Every arrow above is a stage transition that is logged with: actor (user), timestamp, location, quantity in/out, and document reference — this is the backbone of traceability (see Section 16).

7. Complete Database Schema

Convention applied to every table (not repeated below for brevity): id (PK, BIGINT/UUID), created_by (FK->users.id), updated_by (FK->users.id), created_at, updated_at, status (ENUM, table-specific), is_deleted (BOOLEAN, soft delete), tenant_id/plant_id (for multi-plant scalability).

12. Approval Workflow

flowchart LR
 A[Gate Entry] -->|auto| B[Sampling]
 B -->|auto| C[Lab Test]
 C -->|Lab Tech submits verdict| D{QA Manager Review}
 D -- Negotiation --> E[Purchase Officer negotiates] --> F{Purchase Officer Approves Rate}
 F -- Approved --> G[Weighbridge]
 D -- Accepted --> G

 I --> J[Production]

 K --> L[Packing]

 M --> N[Sales Order]
 N --> O{Dispatch Manager Approves Dispatch}
 O --> P{Accountant Approves Invoice}
 P --> Q[Dispatched & Invoiced]

Approval levels by value/exception: - Rate negotiation beyond ±X% of base rate → escalate to Owner/Admin. - Bag rejection beyond a configurable threshold (e.g. >5% of a lot) → escalate to QA Manager before replace/refund is executed. - Credit-note/refund to vendor → requires Accountant + Purchase Officer dual approval. - Dispatch without full payment (credit sale) → requires Accounts approval against customer credit limit.

13. Inventory Movement Flow

Raw Paddy (Gate-In) → Sampling (no stock impact, sample qty negligible/tracked) 
 → Weighbridge (Gross Qty booked as "In-Transit Stock")
 → Unloading (Stock moves to Warehouse Stack OR Production Floor)
 → Quick QC (Accepted Qty stays in flow; Rejected Qty moves to Reject Store)
 → Drying (Stock stays in "WIP - Drying" location; qty unchanged, moisture changes)
 → Milling (Input Paddy Stock decreases; Output Stock created: Brown Rice + Husk + Broken + Waste)
 → Separator (Brown Rice decreases; Cleaned Rice + Impurities created)
 → Shiner x5 (Cleaned Rice decreases; Polished Rice + Bran created, cumulative loss tracked)
 → Color Sorter (Polished Rice splits into Good Grain + Rejected Grain)
 → Length Grader (Good Grain splits into 4 graded lots)
 → Packing (Graded lot stock decreases; Finished Goods stock created)
 → FG Warehouse (Stock held; "aging" clock starts)
 → Dispatch (FG stock decreases; Customer ledger / Sales register updated)
 → By-products (Husk/Bran/Broken/Waste accumulate in By-Product Inventory → sold via separate Sales Order)

Every line above corresponds to a write to inventory and stock_movement, ensuring the sum of all "qty_out" at any node equals "qty_in" (mass-balance reconciliation report — see Section 17).

14. Production Tracking Flow

For every production_batch: 1. Batch created from lots with process_type = Dry or Wet (field note #22). 2. Each stage (machine_logs, dryer, separator_output, shiner_process, color_sorter, length_grading) logs input qty, output qty, loss/recovery %, operator, machine, start/end time. 3. process_time_log captures stage duration → rolled up into total cycle time per batch and machine-wise downtime (field note #1, #8, #26). 4. Recovery % is compared against historical/standard recovery to flag anomalies (e.g., unusually high broken % → quality or machine-setting alert). 5. Batch is "closed" only when all output quantities (main product + by-products + waste) reconcile against input quantity within tolerance.

15. Material Traceability Flow

  • Backward traceability: From any Finished Goods bag (via QR/Barcode) → packing → length_grading → color_sorter → shiner_process → separator_output → production_batch → lots → purchase → gate_entry → vendor. Full chain in seconds.
  • Forward traceability: From any incoming gate_entry/lots, find every production_batch, every packed lot, and every dispatch/customer that received material derived from it — essential for recalls or vendor-quality disputes.
  • Implemented via the parent_lot_id self-reference on lots plus FK chains on every transaction table — this is the single most important integrity rule in the schema.

19.2 Additional industry-standard processes to consider (gap analysis)

  • Vendor Quality Scorecard — auto-rate vendors on rejection %, moisture trends, on-time delivery to drive future PO allocation.
  • Standard Recovery/Yield Norms — define expected recovery % per variety; auto-flag batches deviating beyond tolerance (helps catch pilferage or machine miscalibration).
  • Lot/Batch Genealogy Visualization — a tree/graph UI on top of parent_lot_id for instant audits.
  • Weighbridge Integration (IoT) — direct serial/API capture from weighbridge hardware to eliminate manual entry errors.
  • ANPR Camera at Gate — auto-capture vehicle number to reduce gate clerk error and speed up token issuance.
  • Mobile App for Drivers/Vendors — token status, expected wait time, e-receipt — reduces gate congestion and disputes.
  • Quality-linked Dynamic Pricing — rate formula driven by lab parameters (moisture/broken slabs) rather than manual negotiation alone, with manual override retained for true exceptions.
  • Preventive Maintenance Scheduling — calendar/usage-hour-based triggers in machine_maintenance to reduce unplanned downtime (ties into note #1).
  • Energy & Utility Consumption Tracking — per batch/per machine, common in modern rice-mill ERPs for cost-per-kg analysis.
  • Bagging Material (Empty Bag) Inventory — track consumption of packing material as its own inventory stream.
  • Quality Certificate / Lab Report PDF Generation — auto-generated and attachable to invoices for B2B/export customers.
  • GST/E-Way Bill Integration (India-specific) — auto-generate e-way bills from dispatch for compliant transport documentation.
  • Multi-Plant / Multi-Godown Consolidated Reporting — for groups operating more than one mill, supported by plant_master already in schema.
  • Customer Portal — order tracking, e-invoice download, by-product order booking, mirroring the Vendor Portal.
  • Approval Hierarchy Configuration UI — let Admin define approval chains/thresholds (rate variance %, rejection %) without code changes.
  • Cold-chain/Pest/Fumigation Log — for warehouse compliance and food-safety audits (FSSAI traceability requirements in India).
  • Bank/LC (Letter of Credit) tracking — relevant if mill exports rice; track shipment docs against LC terms.
