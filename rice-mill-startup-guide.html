Section 01

Tech Stack — What & Why

⚙️ Backend

  • Node.js + Express.jsFast REST API, massive ecosystem
  • PostgreSQLRelational DB — perfect for ERP with FKs, transactions, triggers
  • Sequelize ORMModel-based DB access, migrations, seed data
  • JWT (jsonwebtoken)Stateless auth — role-based access per ERP spec
  • JoiRequest validation — critical for data integrity
  • MulterDriver photo upload (Gate Entry requirement)
  • node-cronScheduled jobs: aging calc, maintenance alerts

🖥️ Frontend

  • React 18 + ViteFast dev server, modern build tooling
  • React Router v6Module-based page routing
  • ZustandLightweight state — auth, active batch, notifications
  • TanStack QueryServer-state + cache — no Redux boilerplate
  • Ant Design (antd)Production-grade tables, forms, modals — speeds up ERP UI massively
  • RechartsDashboard KPI charts
  • AxiosHTTP client with interceptors for JWT

🛠️ Dev Tooling

  • ESLint + PrettierCode consistency across team
  • NodemonAuto-restart backend on save
  • dotenvEnv config management
  • Thunder Client / PostmanAPI testing during development
  • pgAdmin 4PostgreSQL GUI for DB inspection

☁️ Infrastructure (Day 1 local, later)

  • Local devNode + Postgres installed locally — keep it simple for 8 days
  • PM2Process manager for staging demo
  • NginxReverse proxy for staging (Day 8)
  • GitHubSource control — commit every day minimum

Project Setup — Run These First

Prerequisites: Node.js 20+, PostgreSQL 15+, Git — all installed on your machine.

1. Create workspace

terminal mkdir rice-mill-erp && cd rice-mill-erp
mkdir backend frontend
git init

2. Backend init

terminal cd backend
npm init -y
npm install express sequelize pg pg-hstore dotenv cors helmet bcryptjs jsonwebtoken joi multer node-cron
npm install --save-dev nodemon eslint prettier

3. Frontend init

terminal cd ../frontend
npm create vite@latest . -- --template react
npm install
npm install axios antd @ant-design/icons react-router-dom zustand @tanstack/react-query recharts dayjs

4. Create database

psql -- open psql terminal
psql -U postgres
CREATE DATABASE rice_mill_erp;
CREATE USER erp_user WITH PASSWORD 'yourpassword';
GRANT ALL PRIVILEGES ON DATABASE rice_mill_erp TO erp_user;
\q

5. Backend .env file

backend/.env PORT=5000
DB_HOST=localhost
DB_PORT=5432
DB_NAME=rice_mill_erp
DB_USER=erp_user
DB_PASS=yourpassword
JWT_SECRET=supersecretkey_change_this
JWT_EXPIRES_IN=8h
UPLOAD_DIR=./uploads

6. Start both servers (two terminals)

terminal 1 — backend cd backend
npx nodemon src/server.js
terminal 2 — frontend cd frontend
npm run dev
✓ Running at
Backend: http://localhost:5000 · Frontend: http://localhost:5173

Section 04

Database Setup with Sequelize

config/db.js

backend/src/config/db.js const { Sequelize } = require('sequelize');

const sequelize = new Sequelize(
  process.env.DB_NAME,
  process.env.DB_USER,
  process.env.DB_PASS,
  {
    host: process.env.DB_HOST,
    dialect: 'postgres',
    logging: false,
    pool: { max:5, min:0, acquire:30000, idle:10000 }
  }
);

module.exports = sequelize;

Sync strategy for prototype (Day 1–2)

// server.js — use sync for rapid prototyping
// NEVER use force:true in production — it drops tables
await sequelize.sync({ alter: true });

// From Day 3+ switch to proper migrations:
// npx sequelize-cli db:migrate
⚠ Migration discipline
Use alter:true only for the first 2 days while you're defining the schema. Switch to Sequelize CLI migrations from Day 3 — this prevents accidental data loss and gives you a proper migration history.

Core model pattern (copy for every table)

models/GateEntry.js const { DataTypes } = require('sequelize');

module.exports = (sequelize) => {
  const GateEntry = sequelize.define('GateEntry', {
    id: { type: DataTypes.UUID, defaultValue: DataTypes.UUIDV4, primaryKey: true },
    token_no: { type: DataTypes.STRING, unique: true, allowNull: false },
    vehicle_no: { type: DataTypes.STRING, allowNull: false },
    driver_name:{ type: DataTypes.STRING },
    driver_mobile:{ type: DataTypes.STRING },
    driver_photo_url:{ type: DataTypes.STRING },
    challan_no: { type: DataTypes.STRING },
    expected_qty:{ type: DataTypes.DECIMAL(10,2) },
    entry_time: { type: DataTypes.DATE, defaultValue: DataTypes.NOW },
    gate_status:{ type: DataTypes.ENUM(
      'waiting_sampling','sampling_done','lab_pending',
      'accepted','rejected','weighed','unloaded','exited'
    ), defaultValue: 'waiting_sampling' },
    is_deleted: { type: DataTypes.BOOLEAN, defaultValue: false },
    // FK: vendor_id, driver_id, po_id — added in models/index.js associations
  }, {
    tableName: 'gate_entries',
    paranoid: true, // adds deletedAt for soft delete
    underscored: true,
  });
  return GateEntry;
};

Section 06

The 8-Day Sprint

Day 1
Foundation — Server, DB, Auth
Backend setup · Models · JWT
▼
  • BE
    Set up Express server with helmet, cors, morgan, dotenv. Wire up Sequelize connection. Test DB connection on startup.
  • DB
    Create models: User, Role, Vendor, Vehicle, Driver. Define associations in models/index.js. Run sync — check tables created in pgAdmin.
  • BE
    Build Auth routes: POST /api/auth/login (email+password → JWT). POST /api/auth/me (verify token, return user+role). Write JWT middleware and RBAC role-check middleware.
  • BE
    Seed: insert Admin user, 4 roles (Admin/Gate/Lab/Production), 3 test vendors.
  • FE
    Create Vite app. Set up React Router with a layout wrapper (Sidebar + TopBar). Build Login page — POST to /api/auth/login, store JWT in Zustand authStore, redirect to dashboard.
  • FE
    Axios client.js: base URL, interceptor to attach Authorization header, 401 → auto logout.
✓ Day 1 Deliverable
  • Server runs, DB connected, tables created
  • Login page works, JWT auth working
  • Role-protected routes working
Day 2
Gate Entry Module
Token · Photo upload · Status flow
▼
  • DB
    Create GateEntry model with full fields from the ERP spec: token_no (auto-generate as "GT-YYYYMMDD-001"), vehicle_no, driver fields, challan_no, expected_qty, gate_status ENUM, vendor_id FK, entry_time.
  • BE
    Routes: POST /api/gate (create entry + auto-generate token), GET /api/gate (list, filterable by status/date), PATCH /api/gate/:id/status (move status forward). Multer for driver photo upload to /uploads.
  • BE
    Token generation service: query DB for today's max token, increment, format as GT-20260702-001. Must be atomic — use DB transaction or sequence to avoid race conditions.
  • FE
    Gate Entry page: Ant Design Form (vehicle no, vendor dropdown, challan, expected qty, driver name/mobile, photo upload). Submit → POST API. Show success with token number.
  • FE
    Gate Queue page: Ant Design Table showing today's entries with status badges (color-coded: waiting=yellow, rejected=red, unloaded=green). Status action buttons per row.
  • FE
    Vendor dropdown: fetch /api/vendors on mount. React-query with useQuery hook.
✓ Day 2 Deliverable
  • Gate security can create entries and see token numbers
  • Driver photo uploads and saves
  • Gate queue list with live status badges
Day 3
Sampling · Lab Testing · Negotiation
QC flow · Verdict · Purchase rate
▼
  • DB
    Models: Sampling (gate_entry_id FK, sample_code, collected_at), LabTest (sampling_id FK, moisture_pct, broken_pct, fm_pct, color, smell, variety, verdict ENUM), Negotiation (lab_test_id FK, old_rate, new_rate, vendor_response), PurchaseOrder (vendor_id, material, qty, rate, po_no, do_no).
  • BE
    Routes: POST /api/sampling (links to gate entry, auto-updates gate status to 'sampling_done'), POST /api/lab-tests, PATCH /api/lab-tests/:id/verdict (triggers status change to accepted/rejected), POST /api/negotiations, PATCH /api/negotiations/:id/respond.
  • BE
    Business rule: when lab verdict = 'rejected' → gate entry status = 'rejected'. When 'accepted' → status = 'lab_accepted'. When negotiation accepted → update purchase rate + status = 'lab_accepted'.
  • FE
    Lab Testing page: list of 'sampling_done' entries. Click any → open test form (input fields for all parameters). Submit verdict with dropdown: Accept / Reject / Negotiation. On Negotiation: show negotiation panel inline.
  • FE
    Status timeline component: show a horizontal step tracker (Ant Design Steps) on the gate entry detail page showing: Gate Entry → Sampling → Lab → Weighbridge → Unloading.
✓ Day 3 Deliverable
  • Full lab QC flow working end-to-end
  • Accept/Reject/Negotiate all update status correctly
  • Status timeline visible per entry
Day 4
Weighbridge · Unloading · Warehouse
Weight · Lot creation · Stack assignment
▼
  • DB
    Models: WeightSlip (gate_entry_id, slip_no, gross_weight, tare_weight, net_weight, weighed_at), Warehouse (code, name, type, capacity), Lot (lot_no auto-gen, purchase linked, material_id, qty, variety, parent_lot_id self-ref), Stack (stack_code, lot_id, warehouse_id, qty, stacked_at).
  • BE
    Weighbridge: POST /api/weighbridge (only allowed for 'lab_accepted' gate entries). Auto-calc net = gross - tare. Creates Purchase record finalizing qty and rate from PO.
  • BE
    Unloading + Lot: POST /api/lots (links to gate entry/purchase, generates lot_no "LOT-YYYYMMDD-001", creates Stack record). PATCH /api/lots/:id/route → { destination: 'warehouse' | 'production' }. Updates gate entry to 'unloaded'.
  • BE
    Inventory service: on lot creation, write to inventory table (lot_id, qty_in, stage='raw_material', warehouse_id).
  • FE
    Weighbridge page: list of 'lab_accepted' trucks. Select one → enter gross weight (tare as default config). Preview net weight. Submit → show slip number.
  • FE
    Warehouse page: Lot list with warehouse/stack info. "Send to Production" button per lot. Current stock table.

Day 5
Production Batch — Full Pipeline
Milling · Separator · Shiner · Color · Grader
▼
  • DB
    Models: ProductionBatch (batch_no, lot_id, process_type dry/wet, input_qty, status), Dryer (batch_id, moisture_before, moisture_after, start/end), MachineLog (batch_id, machine_id, input/output/recovery_pct, operator, start/end), SeparatorOutput, ShinerProcess (stage 1-5), ColorSorter, LengthGrading. Machine master with 10 seed machines.
  • BE
    POST /api/production/batches — create batch from lot. Returns batch with stage checklist. PATCH /api/production/batches/:id/dryer, /milling, /separator, /shiner, /color-sorter, /length-grading — each stage saves output qty and advances batch status.
  • BE
    Recovery % calculated automatically: output_qty / input_qty * 100. Store on machine log. Emit by-product inventory entries (husk, bran, broken) on milling/shiner stage save.
  • FE
    Production Batch page: card-based stage tracker. Each stage = a collapsible card with form inputs. Completing a stage unlocks the next. Visual progress bar across stages.
  • FE
    Active batch dashboard: show all in-progress batches with current stage highlighted. Which machine is running, operator name, start time.
  • FE
    Moisture decision UI: after entering paddy details, ask "Dry or Wet?" — if Wet, show Dryer form first. After dryer, recheck moisture prompt.

Packing + Finished Goods
Batch/Lot · Barcode · FG stock · Aging
▼

    Finished Goods warehouse page: table with columns for SKU, pack size, qty, production date, aged days (highlight red if >30), status badge. Filter bar by pack size and status.

Section 08

Pro Tips for 8 Days

🚀 Build backend first, frontend second — same day
For each module: write the route → controller → model → test in Thunder Client → then build the React page. Don't build FE before BE is working.
🎯 Ant Design saves you 2 days
Use <Table>, <Form>, <Modal>, <Steps>, <Tag> from antd directly. Don't write custom CSS for the first prototype. Focus on logic, not looks.
⚠ Don't build what isn't demoed
WhatsApp, GPS, maintenance, full accounts — stub these as "coming in Phase 2." Every hour on a non-demo feature is an hour stolen from core flow stability.
🔢 Use UUIDs for all PKs from Day 1
Sequelize DataTypes.UUIDV4. Easier to merge data later, better for multi-plant expansion, no integer overflow. One line of config now saves a painful migration later.
📦 TanStack Query = your best friend
useQuery(['gate-entries', filters], fetchFn, {'{'} refetchInterval: 30000 {'}'}) — every list screen auto-refreshes. No manual state sync needed.
⚠ Always test the status machine
The most common bug: status transitions that go backwards or skip steps. Write a status validation service on Day 1 that rejects invalid transitions (e.g., can't go from 'waiting_sampling' directly to 'weighed').
